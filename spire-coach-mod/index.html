Spire Coach Mod

A small coaching experiment for Slay the Spire: turning a run's decisions and outcomes into feedback a player can learn from.

Spire Coach Mod explores how gameplay data could help a player understand patterns in their own decisions without turning the game into an autopilot.

Role
Product framing, interaction direction & prototyping
Focus
Gameplay data and coaching
Status
Early experiment
Work in progress
Problem

It is difficult to learn from a run while you are still playing it.

The game gives immediate feedback, but not always a clear view of the patterns behind a decision or a loss.

My contribution

Framing a feedback loop around player agency.

I am exploring what information could be useful, when it should appear, and how it can teach without telling the player what to do.

Current state

An early experiment with the core direction still taking shape.

The project is not ready to present as a finished mod. The next useful step is turning the idea into a tighter, testable prototype.

The question

How can a game help someone understand their own decisions without removing the discovery that makes the game interesting?

My direction

  • Start from the player's own run data
  • Make feedback specific and explainable
  • Keep recommendations separate from decisions
  • Prefer useful reflection over more on-screen noise

Next step

Define one narrow coaching moment, build the smallest working prototype, and learn whether the feedback helps a player make a different decision next time.

The idea

Slay the Spire is built around repeated decisions. A player chooses cards, routes, upgrades and fights, then sees the consequences. That makes it a good setting for a small experiment in reflective coaching.

The goal is not to create a perfect strategy engine. It is to make the relationship between a decision and its outcome easier to inspect, especially after a run when there is enough distance to think about what happened.

The constraint

Any coaching layer has to respect player agency. If it explains every choice in real time, it can become distracting or flatten the process of learning the game.

I am therefore interested in feedback that is optional, contextual and honest about uncertainty. It should help a player form a better question, not pretend to know the one correct move.

Design question: What is the smallest piece of feedback that can make a player's next run more thoughtful?

Current state

This is an early side project and still a work in progress. The product idea, mod integration and feedback model all need more iteration before the project can be evaluated as a finished tool.

For now, the useful outcome is a clearer direction: build around the player's own decisions, keep the feedback legible, and use a working prototype to find out what is actually worth showing.
